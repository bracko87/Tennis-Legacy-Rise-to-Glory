# E3-A — disposable migration package identity
The installer already provides an ordered 22-file atomic transaction, disabled routing, rollback injection, journal and role isolation. Add an offline manifest of the exact checked-out Git revision, installer/verifier hashes and ordered SQL file SHA-256 values. Refuse SQL, installer or verifier bytes that differ from the committed revision. The CI database installation is bracketed by manifest generation and journal comparison; the final check re-reads the committed candidate and rejects missing, reordered, duplicated or altered entries. No application records are included. This is an integrity check for the existing disposable rehearsal, not a signed approval, production migration or proof that every production dependency exists. It assumes a trusted CI checkout and no concurrent changes to its workspace during install. Actual production migration design still requires an authorized current catalog/restore, shared scheduling and career authority, permission reconciliation and explicit approval.
