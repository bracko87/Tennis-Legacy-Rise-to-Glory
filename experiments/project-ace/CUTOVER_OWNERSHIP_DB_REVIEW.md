# v0.24-B — database ownership rehearsal
Separate disposable ace_cutover_review schema, guarded by database name ace_review. Controller, Ace engine, legacy engine and external-event login roles have distinct privileges. Engine identity comes from session_user, not a caller parameter. Tables are private, engines can only execute tightly scoped functions. Default legacy; explicit competition allowlist, singles, eligibility, unprepared/unstarted state required for new Ace claim. Policy share lock before match row lock serializes claim with disable. Owner is never reassigned; claim/start/complete lock same match row. Repeated identical finish returns already_completed, conflicting receipt or nonowner fails. Revision checks on new start/completion. Review effect and terminal status committed atomically. External worker queues an idempotent handoff rather than directly editing match; pending event blocks start/finalize. Single scheduled event can be resolved by owner as explicit cancelled or walkover. Active or multiple handoffs require manual review and deliberately block release; real medical/travel/guest rules and authoritative winner validation not implemented. No prize/condition effects in these mock handoff rows. Disabling routing leaves owned matches with their original engine; drain tests preserve completed effects. Separate from earlier settlement tables; not yet wired to actual worker or official tables. No production migrations or connections. CI tests added, pending verification.
