# Isolated tournament lifecycle (v0.7 development)

The new lifecycle and tournament store are separate from the single-match local Test Center. They use the same incremental match service. A trusted local scheduler can enqueue up to 100 fixtures with stable local player and court keys. At each authoritative clock boundary it advances live fixtures, records completion once, and admits due fixtures in requested-time / ID order. Shared court or player conflicts defer admission; independent courts run simultaneously. Defaults: 15 real seconds court clearance, 60 real seconds player recovery (pilot values, not production game-clock rules). No future match duration is precomputed. Completion receipt and match state are saved together by atomic file replacement; one writer lock prevents concurrent processes. A process crash may leave a lock; only remove it after verifying the writer is stopped. File replacement does not establish database transaction or power-loss durability guarantees. No official side effects, no production reads or writes.

This is a module/test milestone. The current UI still uses the single-fixture API; production clock conversion, actual tournament scheduler rules, distributed transaction locking, bracket advancement, real player snapshot acquisition, official downstream effects and website integration remain outstanding. Run node experiments/project-ace/tournament-lifecycle.test.cjs for the isolated multi-match test.
