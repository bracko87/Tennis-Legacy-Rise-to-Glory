# v0.18 database persistence review

Disposable PostgreSQL 16 service in GitHub Actions only. No Supabase migrations, production credentials, production API or hosted project. SQL resides in experiments/project-ace/postgres-review.sql, outside the deployment migration directory. Database name ace_review is required by installer; Node transport hardcodes 127.0.0.1, database and worker role, requires explicit opt-in and password. CI passwords are throwaway test constants, not account secrets.

One world revision protects an atomic transaction containing manifest, per-match rows, immutable match receipts and immutable prize transactions. Updates lock the world row and compare expected revision; losing concurrent writers fail rather than replaying stale coaching. Load reconstructs the existing world contract from the records in one SQL snapshot. No client role grants, private schema, RLS enabled, invoker functions. Trusted worker can access all worlds in this disposable database; not multi-tenant user authorization. Current write call still serializes and sends the complete world, even though unchanged match rows are not rewritten. No incremental event streaming or distributed resource locks yet. Test attempts competing writers, restarts, completes tournament, tampers with committed receipts/prizes and checks rollback, repeats settlement. Local browser still uses file store; this is a separate database worker harness, not deployment. Production RLS/auth, official adapters, worker service and performance tuning remain gated.
