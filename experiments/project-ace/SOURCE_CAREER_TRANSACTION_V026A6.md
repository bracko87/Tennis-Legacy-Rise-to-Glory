# v0.26-A6 — transactional career projection
Sixteenth disposable package. Explicit competition opt-in before admission; default off. Controller imports revisioned synthetic player state. Match start captures both players atomically after resource locks, binds health to readiness and blocks later opted-in starts with prior unprocessed played career batch. Controller generates existing JS proposal from stored snapshot and owned effect. Application requires synchronized result projection, exact stored snapshot and receipt, immutable match owner/revision, exact current career states/revisions, ordered two players, idempotency keys, structural condition/equipment invariants. Both updates and immutable effect rows in one transaction; exact replay returns stored result, conflicts and mid-match state changes roll back both. SQL does not independently replay all formulas, verify proposal hashes or score/point authenticity; controller trusted for proposal generation. No automatic rebase, no official career/account/injury writes, no global coverage for non-opted matches, no support for non-play career batch; these are explicit blockers for production. Tests include missing career state, sync requirement, second-player invalid gear rollback, stale revision, concurrent replay, permission denial. CI pending. Production untouched.
