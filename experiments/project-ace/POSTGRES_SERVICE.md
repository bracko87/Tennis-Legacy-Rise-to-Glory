# v0.19 persistent isolated worker service

Corrected v0.18 test fixture: next Monday is week 2, day 1, not week 1, day 8. Existing calendar validation is unchanged. PostgreSQL service layer uses the existing review-only adapter, authorized worker identity and trusted clock source. Background ticks reload state and retry revision conflicts at most twice after the first attempt; user coaching is never automatically retried. Reads expose only sanitized, committed world views. The loop serializes its own ticks and backs off on transient errors; shutdown waits for any in-flight tick. Manual process entry start-postgres-worker.cjs requires an existing review world and explicit loopback database configuration. It has no HTTP endpoint, does not create databases and is not used by the local React pilot. No production migrations or credentials.

The service test uses two independent clients, paused/resumed clock, shared database state, restart, owner-only coaching, non-retried command conflict, complete tournament, ranking publication and a single-loop concurrency check. It does not implement distributed leases or multi-tenant authentication; PostgreSQL CAS protects one world revision. Real-time samples after lengthy downtime can still block missed tournament phase slots rather than silently starting past-window games. Official tournament scheduling, injury walkovers, tax, real career side effects and website authentication remain gated.
