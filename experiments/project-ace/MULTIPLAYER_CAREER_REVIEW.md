# v0.14–0.15 private tournament review

ACE_TOURNAMENT_PEER=1 before starting start-tournament.cjs enables a second synthetic local account and a separate multiplayer draw directory; old single-manager tournaments are retained. Admin controls p0 (optionally imported private player); peer controls p2 in the demo. Both enter the main draw in opposite halves. Both may spectate, only their own matches permit commands, and both receive the same elapsed scoreboard. Admin cannot coach the peer's player. Peer cannot create a draw. Peer identity is fixed to the configured synthetic allowlist; no arbitrary account IDs or production login. Manual, hybrid and automatic choices are separate. React pilot uses existing local server. Browser acceptance and distributed database ownership remain outstanding.

career-support.cjs is an independent pure adapter based on existing SQL: missing gear multipliers, condition threshold <20 and same-category retirement/replacement at 0, resolved staff fatigue/injury reduction caps, match risk formula, tournament return date, and explicit Day Off recovery. Equipment wear units are supplied, not the production wear algorithm; replacement tie ordering uses local IDs; recoveryMultiplier ceiling 1.5 is a pilot safety bound; the staff inputs are already-resolved modifiers, not staff contracts; injury risk is a probability, not new injury generation. No actual inventory, staff contracts, injury roll, walkover, automatic day-off, ranking or payment. These functions are not yet wired to the live match/draw worker; no changes to existing saved tournaments. No production queries/writes.
