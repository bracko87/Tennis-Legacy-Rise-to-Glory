# v0.17 isolated stress and security review

Default scheduler capacity is unchanged at 100 records. Trusted test configuration can set maxJobs up to 256. No production load limits changed. Avoid cloning live match histories at unrelated boundaries; lastNow still advances on the private cloned scheduler state. Native test schedules 200 independent courts and 400 synthetic players, advances all from the same start, finishes, then compares the entire result with a persisted mid-run restart. It prints actual CPU elapsed, points, serialized size and peak process RSS. This is a single-machine batch simulation, not a benchmark of 200 simultaneous HTTP clients or production database throughput. Tests also check exclusive writer, rejection of wrong-kind and unserializable state without overwriting the previous save, repeated completion receipts, hostile origins, oversized and malformed JSON, invalid tactic values, forged/expired tokens, spectator privacy and unauthorized commands. No power-loss durability or distributed locks proven. No deployment, production reads or writes. The real-world worker still has a one-draw limit; synthetic schedule/reward tables and local identity remain. Production integration requires an isolated database-backed worker, official scheduling and settlement adapters, live authentication/RLS, recovery policy for blocked matches and separate approval.
